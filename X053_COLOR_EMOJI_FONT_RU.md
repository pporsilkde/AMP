# ArenaMP X053 — цветные эмодзи OpenMoji в чате

База: ArenaMP X052.

## Коротко

Напрямую подключить `OpenMoji-color-cbdt.ttf` как шрифт MyGUI **нельзя** — он не отрисуется вообще. Но встроить его содержимое можно, и это сделано: эмодзи теперь цветные, прямо в тексте чата.

## Почему TTF не работает как есть

Я разобрал загруженный файл. Факты, а не предположения:

```
таблицы:      CBDT, CBLC, GSUB, OS/2, cmap, glyf, head, hhea, hmtx, loca, maxp, name, post
unitsPerEm:   1024
strike:       ровно один, ppem 99x99, bitDepth 32
glyf:         из первых 400 глифов 399 имеют numberOfContours == 0
cmap:         1898 записей, латиницы нет, кириллицы нет
```

Две независимые причины, по которым MyGUI это не нарисует:

1. **Нет цветного пути.** `ResourceTrueTypeFont` растеризует через FreeType без флага `FT_LOAD_COLOR` и складывает результат в одноканальную alpha-текстуру. Цвет физически некуда положить.

2. **Не совпадает размер страйка.** Единственный страйк — 99 px. MyGUI запрашивает произвольный размер (18–20 px для чата). Совпадения нет. При этом таблица `glyf` присутствует, поэтому FreeType считает шрифт масштабируемым, успешно выполняет `FT_Set_Char_Size` и берёт **контур** вместо битмапа. А контуры пустые. На экране — ничего.

То есть если бы я просто прописал этот TTF в `.omwfont`, вы получили бы не квадраты, а пустоту, что хуже.

Дополнительно: в шрифте нет U+263B ☻, U+2713 ✓ и U+2717 ✗ — OpenMoji покрывает эмодзи, но не дингбаты. Эти три слота палитры X052 заменены на U+1F60A, U+2714 и U+274C, которые в шрифте есть.

## Что работает: ManualFont-атлас

MyGUI умеет `ResourceManualFont` — текстура плюс прямоугольники глифов. Глифы такого шрифта рисуются текстурированными квадами, **умноженными на цвет текста виджета**. Значит RGBA-атлас сохраняет собственные цвета, если цвет текста белый. Это и есть путь к цветным эмодзи в OpenMW 0.47.

Ограничение, которое определило конструкцию: **у MyGUI нет fallback-шрифтов**. Один виджет — один шрифт. Поэтому нельзя «добавить эмодзи-шрифт рядом» — атлас обязан содержать и буквы тоже, иначе переключение чата на эмодзи-шрифт потеряет весь обычный текст.

Итог — один атлас `ArenaMPChatColor`:

- латиница, Latin-1, Latin Extended-A, греческий, кириллица, пунктуация, валюты — растеризованы **белым**, поэтому привычные теги `#RRGGBB` (включая цвет ника из X052) продолжают их подкрашивать;
- 109 эмодзи из OpenMoji — с **запечёнными собственными цветами**;
- служебные глифы MyGUI: `cursor`, `selected`, `selected_back`, `substitute`.

Готовый атлас: 1024×256 RGBA, 659 глифов, высота строки 22 px, 167 КБ.

Оговорка про цвет: если эмодзи попадёт внутрь цветного участка строки, он будет подкрашен этим цветом. В теле сообщения после имени уже стоит `color.White`, так что в обычном чате эмодзи выглядят правильно.

## Генератор

`tools/arenamp_make_emoji_font.py` — распаковывает битмапы из CBDT, растеризует текстовый шрифт, пакует всё в один PNG и пишет MyGUI XML.

```bash
python3 tools/arenamp_make_emoji_font.py \
    --text-font  files/mygui/DejaVuLGCSansMono.ttf \
    --emoji-font files/mygui/OpenMoji-color-cbdt.ttf \
    --out-dir    files/mygui \
    --size 18
```

Требует `Pillow` и `fonttools`.

**Важно.** Атлас в архиве собран из `DejaVuSansMono.ttf`, а не из вашего `DejaVuLGCSansMono.ttf` — этого файла нет в патч-подмножестве, которое вы присылали. Это тот же самый шрифт DejaVu, LGC — просто его сборка с урезанным набором символов, метрики совпадают. Но чтобы гарантировать попиксельное совпадение с остальным интерфейсом, **прогоните генератор один раз на своём дереве** командой выше. Сам OpenMoji TTF в рантайме не нужен — только для генерации.

## Включение

По умолчанию всё выключено, поведение X052 сохраняется. Чтобы включить цвет:

```ini
[Chat]
menu font = ArenaMPChatColor
emoji font = ArenaMPChatColor
```

`GUIChat::ensureChatFontLoaded()` подгружает `ArenaMPChatColor.xml` через `MyGUI::ResourceManager` в `try/catch`. Если атласа нет или он битый — в лог уходит предупреждение, шрифт откатывается на `DejaVuLGCSansMono`, палитра — на ASCII. Отсутствующий атлас не может уронить интерфейс.

Ресурс грузится из C++, а не объявляется в `core.xml`, именно ради этого отката, и заодно чтобы патч не трогал файл, которого нет в вашем подмножестве.

## Изменённые файлы

Изменены: `apps/openmw/mwmp/GUI/GUIChat.cpp`, `apps/openmw/mwmp/GUI/GUIChat.hpp`, `files/settings-default.cfg`, `files/mygui/CMakeLists.txt`.

Новые: `files/mygui/ArenaMPChatColor.xml`, `files/mygui/ArenaMPChatColor.png`, `tools/arenamp_make_emoji_font.py`.

`ArenaMPChatColor.png` — бинарный, в unified diff он не помещается, поэтому он есть только в архиве. При наложении патча на своё дерево скопируйте PNG из архива вручную либо просто прогоните генератор.

## Проверка в игре

1. Собрать X053, выставить обе настройки в `ArenaMPChatColor`.
2. `Y` → **Эмодзи**: 20 кнопок с цветными OpenMoji.
3. Вставить эмодзи в сообщение и отправить — цвет должен сохраниться в истории чата у обоих игроков.
4. Написать сообщение с кириллицей и латиницей — буквы должны выглядеть как раньше, без потери символов.
5. Проверить цвет ника из X052 — имя по-прежнему подкрашивается.
6. Переименовать `ArenaMPChatColor.png` и перезапустить: в лог должно уйти предупреждение, чат — вернуться к обычному шрифту и ASCII-палитре, без падения.

## Статические проверки

`X053_player_menu_emoji_harness.py` дополнительно к проверкам X052 контролирует:

- атлас существует и является именно `ResourceManualFont`;
- присутствуют все четыре служебных глифа MyGUI;
- в атласе есть U+0041, U+0410 и U+1F602 — то есть шрифт не потеряет обычный текст, раз fallback у MyGUI нет;
- **каждый** кодпоинт Unicode-палитры C++ реально присутствует в атласе, иначе он отрисуется квадратом;
- оба файла атласа прописаны в `files/mygui/CMakeLists.txt`;
- все три ключа `[Chat]` есть в `settings-default.cfg` и читаются из C++.

Прямой патч проверен наложением на дерево X052, обратный — восстановлением X052.
