# ArenaMP X044 — NPC перестали двигаться (регрессия X034)

База: кумулятивный X043a. Формат пакетов не менялся, серверные Lua-скрипты не менялись.
Патч только клиентский: `apps/openmw/mwmp/`.

## 1. Причина

Виноват безусловный `actor->setAi()`, добавленный в X034 в
`Cell::prepareDedicatedActorsForAuthority()`.

`BaseActor` инициализирует `aiAction = 0`, а `0` — это `CANCEL`, и ветка CANCEL в
`DedicatedActor::setAi()` выполняет `sequence.clear()`.

Цепочка при входе в любую ячейку (достаточно даже одного игрока):

1. сервер присылает позиции/статы актёров -> `initializeDedicatedActors()` создаёт
   DedicatedActor'ов ещё до передачи авторитета;
2. приходит `ID_ACTOR_AUTHORITY` -> `prepareDedicatedActorsForAuthority()` вызывает
   `setAi()` у каждого из них -> `aiAction` там всё ещё дефолтный CANCEL ->
   **у каждого NPC стирается весь AiSequence, включая AiWander**;
3. `uninitializeDedicatedActors()` + `initializeLocalActors()` -> LocalActor'ы
   создаются уже с пустой последовательностью.

Пакеты из записи NPC заполняются только при создании custom data актёра, то есть
пока ячейка загружена, они не восстанавливаются. NPC стоит на месте до выгрузки
ячейки.

Бой при этом работал «+- адекватно», потому что `AiCombat` создаётся заново через
`engageCombat`/`onHit` и не зависит от стёртого Wander.

Попутно найдены ещё две связанные проблемы того же патча:

- `setAi()` пишет `AI_Fight = 0` в реальный Ptr. Настройка остаётся на ссылке и
  после перехода актёра под наш авторитет, поэтому NPC становился пацифистом
  навсегда и реагировал только на удар.
- `LocalActor::updateAiState()` вызывал `actorList->reset()` на **общем** сетевом
  ActorList прямо внутри цикла `Cell::updateLocal`. reset() чистит уже накопленные
  position/animFlags/stats записи всех актёров, обработанных ранее в этом же тике,
  поэтому часть пакетов движения просто не уходила на другие клиенты.

## 2. Что исправлено

### 2.1 AI применяется только если он действительно приходил

`apps/openmw/mwmp/DedicatedActor.hpp`, `DedicatedActor.cpp`, `Cell.cpp`

- у `DedicatedActor` появился публичный флаг `hasReceivedAi` (по умолчанию false);
- `Cell::readAi()` выставляет его в true при получении настоящего `ID_ACTOR_AI`;
- `DedicatedActor::setAi()` выходит сразу, если флага нет;
- `prepareDedicatedActorsForAuthority()` вызывает `setAi()` только при `hasReceivedAi`.

Явный CANCEL от сервера или другого клиента продолжает работать как раньше.

### 2.2 Возврат естественной агрессии

`apps/openmw/mwmp/Cell.cpp`, новый хелпер `restoreOwnedActorAi()`

При переходе актёра под наш авторитет `AI_Fight` восстанавливается из его
собственной записи (ESM::NPC / ESM::Creature, `mAiData.mFight`), но **только если
там сейчас 0**, то есть только тот ноль, который записал puppet-код. Скрипт,
законно выставивший `Fight 0`, не трогается.

Вызывается в трёх точках перехода DedicatedActor -> LocalActor:
`prepareDedicatedActorsForAuthority()`, ветка readCellChange и
`initializeLocalActor()`.

### 2.3 Восстановление уже стёртых пакетов

Тот же `restoreOwnedActorAi()`: если у актёра, который становится нашим,
AiSequence полностью пуст, а в его записи есть AI-пакеты, они заливаются обратно
через `AiSequence::fill(record.mAiPackage)`.

Это нужно как лечение уже сломанного мира: NPC, у которых текущая сборка уже
стёрла Wander, начнут ходить сразу, без выгрузки ячейки и рестарта сервера.

Честное ограничение: сторонний явный CANCEL теперь не «запоминается» через смену
авторитета — такой актёр получит свои записанные AI-пакеты обратно. До X034 такой
актёр вообще оставался без AI навсегда, так что это не ухудшение, но знать об этом
стоит. Мёртвые актёры не заливаются.

### 2.4 Heartbeat AI больше не рвёт исходящий батч

`apps/openmw/mwmp/LocalActor.cpp`, `LocalActor.hpp`

- AI-снимок отправляется через **приватный** `ActorList` на стеке — ровно тем же
  способом, каким это давно делают `sendEquipment()` и `sendDeath()`. Общий батч
  `Cell::updateLocal` больше не сбрасывается;
- добавлен `mAiStateInitialized`: первый апдейт нового LocalActor'а берёт тихий
  baseline вместо рассылки COMBAT_END на каждого idle NPC в ячейке;
- heartbeat отправляется только когда есть бой или подвешенный маршрут домой;
  простаивающий NPC не шлёт ничего вообще;
- `forceUpdate` тоже больше не порождает пакет, если состояния AI нет.

Смена состояния боя, набора целей и маршрута публикуется мгновенно, как в X034.

## 4. Что проверить в игре

1. Зайти в город одним игроком: NPC должны ходить по своим маршрутам сразу после
   входа в ячейку.
2. Зайти в интерьер и выйти — маршруты сохраняются, «замороженных» NPC нет.
3. Второй игрок заходит в ту же ячейку и перехватывает авторитет: NPC продолжают
   ходить у обоих.
4. Подойти к агрессивному существу, не атакуя его: оно должно напасть само
   (проверка возврата `AI_Fight`).
5. Проверить, что бой/возврат домой из X034 не сломались: преследование через
   дверь, потеря цели, возврат по breadcrumbs.
6. На уже «замороженном» мире: после установки этой сборки NPC должны ожить без
   удаления серверных JSON ячеек.

## 5. Что проверено здесь, а что нет

Проверено:

- баланс скобок/круглых скобок во всех пяти изменённых файлах (0/0);
- существование всех использованных API по присланному дереву:
  `CreatureStats::getAiSetting/setAiSetting`, `Stat<int>::getBase`,
  `AiSequence::isEmpty/fill`, `ESM::NPC::mAiData/mAiPackage`,
  `ESM::Creature::mAiData/mAiPackage`, `ActorList::addAiStateActor/sendAiActors`;
- что серверная проверка авторитета в `ProcessorActorAI` использует
  `actorList.guid`, который выставляется в `ActorProcessor.cpp` из GUID соединения,
  а не из тела пакета — поэтому приватный `ActorList` на стеке (без вызова
  `reset()`, который заполняет guid) отправляется корректно, как и у
  `sendEquipment()`/`sendDeath()`;
- `X044_ai_idle_movement_harness.py` — 15 проверок, включая воспроизведение самой
  регрессии; результат OK.

Не проверено:

- полная сборка MSVC под Windows здесь не запускалась;
- поведение при 3+ игроках в одной ячейке проверялось только логически.
