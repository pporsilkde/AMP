# ArenaMP X050 — Group Helper / интеграция группы в Player Menu

База: ArenaMP X049a (Player Menu Chat + MyGUI UString compile fix).

## Что реализовано

### Серверное ядро `groupHelper.lua`

`server/scripts/groupHelper.lua` — единый серверный источник групповой логики.

- постоянный registry групп: `server/data/custom/groupHelper.json` (путь TES3MP `custom/groupHelper.json`);
- членство привязано к account name, а не к временному PID, поэтому переживает релог;
- создание группы;
- приглашение игрока онлайн;
- принять/отклонить приглашение;
- выход из группы;
- исключение участника лидером;
- передача лидерства;
- автоматический выбор нового лидера при выходе текущего;
- роспуск группы;
- `/groupui ...` для Player Menu и `/group ...` как серверный fallback;
- публичный API: `GetPlayerGroupId`, `GetPlayerGroup`, `GetGroupMembers`, `ArePlayersInSameGroup`, `IsLeader`, `IsFriendlySummon`, `AwardServerQuestXp`.

Старый `TeamGroup.lua` одновременно с X050 подключать не нужно: его обработчики приглашений, Journal и ObjectHit будут дублировать `groupHelper`.

### Вкладка «Группа» в новом чате / Player Menu

Вместо заглушки вкладка содержит:

- название создаваемой группы;
- поле имени/аккаунта игрока;
- Создать;
- Пригласить;
- Исключить;
- Передать лидерство;
- Выйти;
- Распустить;
- Принять/Отклонить приглашение;
- Обновить;
- отдельные кнопки `Синхронизация журнала: ВКЛ/ВЫКЛ` и `Синхронизация топиков: ВКЛ/ВЫКЛ`;
- список участников со статусами: лидер, offline, та же ячейка/получает XP, другая ячейка.

Состояние приходит через скрытый префикс `@@AMP_GROUP@@` и перехватывается `GUIChat`, поэтому служебные строки не видны в истории чата.

## Journal / Topic sync

Оба режима независимы и по умолчанию ВЫКЛЮЧЕНЫ.

Участник участвует в конкретной синхронизации только если сам её включил. Это предотвращает неожиданное изменение журнала игрока после вступления в группу.

При включении режима X050 сначала объединяет уже накопленное состояние всех онлайн-участников группы, у которых тот же режим включён. После этого новые изменения отправляются сразу.

Journal:

- сливаются уникальные server-side journal entries;
- существующие записи не удаляются;
- старые этапы не откатываются;
- после изменения вызывается штатный `Players[pid]:LoadJournal()`;
- `Journal, ...` console command не используется.

Topics:

- объединяются известные серверу topics;
- существующие topics не удаляются;
- после изменения вызывается штатный `Players[pid]:LoadTopics()`.

При повторном входе игрока включённые режимы делают reconciliation с текущими онлайн-участниками группы.

## Групповой XP

Только XP за:

1. убийства;
2. нативное продвижение/завершение квестов;
3. XP reward серверных ArenaMP-квестов.

Другая XP (навыки, книги, путешествия, торговля и т.п.) остаётся индивидуальной.

Правило:

- если источник XP не в группе — получает 100% сам;
- если он в группе — берутся только ONLINE участники его группы, которые находятся в ТОЙ ЖЕ CELL в момент server event;
- исходная награда делится поровну на количество таких участников;
- участники в другой ячейке XP не получают и в делитель не входят.

Пример: kill = 90 raw XP, в cell находятся убийца + 2 участника группы -> каждому 30 raw XP, после чего применяется обычный серверный XP/difficulty multiplier.

### Защита от двойного XP при Journal sync

X050 включает `server party xp=true` в server-enforced `[XP Leveling]`.

Клиент при kill/quest progression не зачисляет XP сразу. Он отправляет transient key `amp-xp|v1|...` в уже существующем PlayerLevel state. Сервер:

1. вырезает этот ключ до сохранения персонажа;
2. сопоставляет его с недавним реальным `ActorDeath` или `PlayerJournal` event;
3. сначала отправляет клиенту очищенный server-owned PlayerLevel;
4. затем распределяет награду;
5. получатели применяют её через скрытый `@@AMP_XP@@` control message.

Journal entry, пришедший участнику через group sync, может создать локальный XP request, но у получателя нет соответствующего server-originated `PlayerJournal` event, поэтому такой запрос не проходит проверку и повторная награда не выдаётся.

Kill от player-owned summon также связывается с владельцем summon для группового XP.

Ограничение текущего server API: `ActorDeath` не предоставляет Lua серверу уровень погибшего NPC/creature, поэтому raw kill amount рассчитывается существующей клиентской XP-системой с server-enforced настройками, имеет верхний лимит и принимается только при наличии подходящего server ActorDeath event. Само решение о получателях/делении и фактическая выдача XP выполняются серверной групповой логикой.

## Friendly summons

Два слоя защиты:

1. `OnObjectHit` — если игрок ударил summon участника своей группы, default handler отменяется и отправляется `StopCombat`;
2. каждые 2 секунды `GroupHelper_SummonTick` проходит загруженные player-owned summons и отправляет `StopCombat` относительно владельца и членов его группы в той же cell.

Это повторяет сильную сторону референсного `TeamGroup.lua`, но использует единый API X050.

## Проверка в игре

1. Собрать клиент и сервер X050.
2. Зайти двумя аккаунтами.
3. Y -> `Группа` -> создать группу.
4. Ввести имя второго игрока -> Пригласить.
5. Второй игрок открывает `Группа` -> Принять.
6. У обоих включить Journal sync; сделать новый journal stage у одного и проверить появление у второго.
7. Аналогично включить Topics sync и открыть новый dialogue topic.
8. Оставить обоих в одной cell и убить NPC: сумма группового XP должна соответствовать одной исходной награде, разделённой поровну.
9. Перевести второго в другую cell и повторить: XP получает только участник в cell события.
10. Призвать существо, ударить его вторым участником: summon не должен оставаться в combat с союзником.
11. Проверить kick / leader / leave / disband.
12. Перезапустить сервер и войти снова: группа должна восстановиться по account name.

- изменённые Lua: `texluac -p`;

- `X050_group_helper_harness.py` проверяет критические integration markers и layout widgets;
- unified patch проверяется через `patch --dry-run` на X049a tree.

Полной MSVC/Ninja сборки здесь нет, поэтому C++ ABI/MyGUI совместимость окончательно подтверждается вашей реальной Windows сборкой.
