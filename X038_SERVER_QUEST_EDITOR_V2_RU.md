# ArenaMP X038 — Server Quest Editor v2

X038 продолжает X037 и не меняет QuestSync-протокол. Основное изменение — полноценный иерархический редактор серверных квестов прямо в игре. Ручной JSON и команды `/quest ...` остаются доступны, но для обычной работы модератору они больше не обязательны.

## Как открыть

Войти под Moderator/Admin и написать:

`/quest`

Далее: **Quests** → выбрать существующий квест или **New quest**.

Главная карточка квеста теперь разделена на:

- **Name** — отображаемое имя;
- **Giver** — NPC-квестодатель;
- **Topics** — зелёные темы диалога;
- **Offer** — предложение квеста и варианты ответа до старта;
- **Stages** — стадии, журнал, диалог, условия, Choices, награды и переходы;
- **Validate** — проверка definition;
- **Publish/Disable** — публикация/отключение;
- **Test me** — сбросить своё тестовое состояние и запустить квест заново.

Любая правка опубликованного квеста автоматически переводит его в **draft**. Для возврата в игру квест нужно снова Validate → Publish.

## Выбрать NPC прямо из игры

1. Открыть `/quest` → Quests → нужный квест → **Giver**.
2. Нажать **Pick in game**.
3. Закрыть сообщение редактора.
4. Активировать нужного NPC обычной кнопкой действия.

Сервер сохранит:

- `refId`;
- текущую cell;
- `uniqueIndex` экземпляра.

Режим выбора выключается после первой успешной активации. Если выбран неправильный объект — снова нажать Pick in game.

**Clear uniqueIndex** оставляет привязку по `refId + cell`, но убирает привязку к конкретному экземпляру. Это полезно для NPC, которые могут быть пересозданы/перемещены модом.

## Зеленые Topics

`Topics` → **Add**:

`topic_id | Текст темы`

Пример:

`arena_caius_drink_topic | немного выпивки`

`Select/Edit` позволяет:

- изменить отображаемый текст;
- включить/выключить тему;
- удалить тему.

На клиенте опубликованный server topic остаётся зелёным и server-authoritative.

## Offer — предложение квеста

`Offer` → **Edit dialogue** задаёт первую реплику NPC до принятия квеста.

`Offer` → **Choices** управляет ответами игрока.

Формат Add/Edit Choice:

`choice_id | start/advance/none | targetStage/- | Текст ответа`

Пример принятия:

`accept | start | - | Хорошо, я помогу.`

Пример отказа:

`decline | none | - | Не сейчас.`

## Stages

`Stages` → **Add**:

`index | Запись журнала | Реплика NPC`

Пример:

`10 | Кай попросил принести бутылку мацта. | Ну что, получилось найти выпивку?`

После выбора стадии доступны:

- **Journal** — изменить запись журнала;
- **Dialogue** — изменить ответ NPC;
- **Requirements** — условия самой стадии;
- **Choices** — варианты ответа игрока;
- **Rewards** — награды/actions при входе в стадию;
- **Transitions** — разрешённые переходы;
- **Flags** — initial/complete/fail;
- **Delete** — удалить стадию.

При удалении стадии переходы `stage.next`, указывающие на неё, удаляются. Если удалена initial stage, редактор выбирает самую раннюю оставшуюся стадию. Choices с ручной ссылкой на удалённую stage будут пойманы Validate.

## Requirements

Requirements можно добавлять и на стадию, и на **конкретный Choice**.

Форматы:

- `level | >= | 5`
- `gold | >= | 500`
- `item | potion_mazte_01 | >= | 1`
- `questStage | another_quest | >= | 20`
- `questState | another_quest | == | completed`
- `playerVariable | key | == | value`
- `serverVariable | key | == | value`
- `staffRank | >= | 1`

Если requirement стоит на Choice, сервер вообще не отправляет этот вариант ответа клиенту, пока условие не выполнено. При клике условие проверяется повторно на сервере.

## Rewards / Actions

В стадии открыть **Rewards** → Add.

Форматы:

- `gold | 250`
- `xp | 125`
- `item | potion_health_standard | 1`
- `takeItem | potion_mazte_01 | 1`
- `message | Текст сообщения`

XP использует существующий server XP multiplier, если definition не задаёт абсолютный режим.

## Transitions

`Transitions` → Add → ввести номер существующей стадии, например:

`20`

Удаление перехода выполняется через **Delete selected**.

## Flags

Внутри стадии → **Flags**:

- **Set initial** — сделать эту stage стартовой;
- **Toggle complete** — стадия завершает квест;
- **Toggle fail** — стадия проваливает квест.

`complete` и `fail` взаимоисключающие: включение одного автоматически выключает другое.

## Пример Кая Косадеса

Встроенный `arena_caius_drink` из X037 остаётся рабочим и является готовым примером X038.

Путь для просмотра:

`/quest` → **Quests** → `Выпивка для Кая`.

Структура:

- giver: `caius cosades`;
- зелёная тема: `немного выпивки`;
- Offer: Кай просит принести выпивку;
- Choice `accept` начинает stage 10;
- stage 10 показывает `hand_over` только при наличии `potion_mazte_01`;
- Choice `hand_over` переводит на stage 20;
- stage 20 забирает мацт и выдаёт 75 gold + 40 XP;
- stage 20 = complete.

Можно открыть каждый узел редактора и использовать этот квест как образец без ручного JSON.

## Права

- обычный Player не видит функции редактирования;
- Moderator может создавать/редактировать/валидировать;
- публикация Moderator зависит от `config.serverQuests.moderatorsCanPublish`;
- Admin/Owner имеет полный доступ.

## Совместимость

X038 не меняет клиентский QuestSync transport X037. Все клиентские C++ файлы X037 остаются прежними. Серверный X038 лучше использовать вместе с полным X038 cumulative, но по wire-format X037 client совместим с X038 server.
